# NewYearBot Project

Этот проект — бэкенд-система для Telegram-бота, предназначенного для организации новогодней вечеринки. Он построен на микросервисной архитектуре с использованием FastAPI, Kafka, PostgreSQL и MinIO.

## Архитектура

Система состоит из нескольких независимых сервисов. **Основное межсервисное взаимодействие построено на асинхронном обмене сообщениями через Kafka.**

Каждый сервис также предоставляет HTTP API (FastAPI), которое используется в основном для health-check'ов, получения динамического меню (оркестратором) и тестирования. Вся основная бизнес-логика (создание пользователя, обработка билета, бронирование подарка) инициируется и обрабатывается через топики Kafka.

-   **tg_bot_service**: (FastAPI + Aiogram)
    -   Точка входа для всех взаимодействий с пользователем в Telegram.
    -   Принимает команды, обрабатывает нажатия кнопок, управляет FSM-состояниями.
    -   Отправляет команды в Kafka (например, `user.user.create`) и получает уведомления для пользователя (например, `notification.send`).

-   **orchestrator_service**: (FastAPI)
    -   Центральный узел, который *может* получать HTTP-запросы (например, от `tg_bot_service` для скачивания билета), но в основном служит для определения бизнес-логики.
    -   Содержит логику "меню" (`/api/v1/menu`), которую бот динамически загружает.
    -   Направляет команды в другие сервисы через Kafka.

-   **user_service**: (FastAPI + PostgreSQL)
    -   Слушает топик `user.user.create` для создания/обновления пользователей.
    -   Хранит данные о пользователях.

-   **wishlist_service**: (FastAPI + PostgreSQL)
    -   Управляет "вишлистами" подарков.
    -   Слушает топики Kafka (например, `wishlist.item.add`, `wishlist.item.book`, `wishlist.view.request`) для выполнения всех операций.
    -   Отправляет события о результатах (например, `wishlist.view.owner_success`) обратно в Kafka.

-   **ticket_service**: (FastAPI + PostgreSQL + MinIO)
    -   Слушает топик `ticket.ticket.create` для обработки и парсинга новых PDF-билетов.
    -   Сохраняет файлы в MinIO и данные в БД.
    -   Отправляет события-уведомления (например, `notification.send.tickets`) по завершении.

-   **music_uploader_service**: (FastAPI)
    -   Слушает топик `music.track.add` для добавления музыки в плейлист.

-   **notification_service**: (FastAPI + PostgreSQL)
    -   Центральный обработчик уведомлений.
    -   Получает события от *всех* других сервисов (например, "билет обработан", "подарок забронирован") и отправляет их в топик `notification.send`, который слушает `tg_bot_service`.

-   **Kafka**: **Основной брокер сообщений** для всего асинхронного взаимодействия между сервисами.
-   **PostgreSQL**: Основная база данных для сервисов (user, ticket, wishlist, notification).
-   **MinIO**: S3-совместимое хранилище для файлов (PDF билетов).

## Локальный запуск

Вся инфраструктура и зависимости сервисов управляются через `docker-compose`. Poetry используется внутри контейнеров для управления зависимостями Python.

1.  **Конфигурация**:
    Скопируй `.env.example` в `.env` в корне проекта и заполни необходимые переменные:
    -   `BOT_TOKEN` (токен твоего Telegram-бота)
    -   `ADMIN_TELEGRAM_IDS` (список ID администраторов)
    -   `WIFI_PASSWORD` (пароль от Wi-Fi для бота)
    -   (Остальные переменные, как правило, уже настроены для `docker-compose`)

2.  **Сборка и запуск**:
    Выполни одну команду в корне проекта:
    ```bash
    docker-compose up --build
    ```
    Эта команда:
    -   Соберет образы для всех сервисов, установив все `poetry` зависимости.
    -   Запустит Zookeeper, Kafka, MinIO и базы данных PostgreSQL.
    -   Запустит сервис `kafka-setup`, который автоматически создаст все необходимые топики в Kafka.
    -   Запустит каждый микросервис. При запуске каждый сервис **автоматически применит свои миграции Alembic** (`alembic upgrade head`) перед стартом веб-сервера `uvicorn`.

3.  **Готово**:
    После завершения запуска всех контейнеров бот готов к работе в Telegram.
